# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to
[Semantic Versioning](https://semver.org/).

## Unreleased

- A `Purchaser` that throws a `PurchaseError` now has that error passed through unchanged, so its code is kept.
- Added `Purchaser` and `PurchaseStore.purchase(_:using:options:)`, which purchase in a presentation context the app supplies, and, in `InAppPurchaseUI`, `purchase(_:confirmIn:options:)` for a `UIScene`, a `UIViewController`, or an `NSWindow`. On visionOS, a purchase can now be confirmed in a scene as well as through `@Environment(\.purchase)`.
- `MockPurchaseClient` keeps entitlements as StoreKit does: a purchased or sent non-consumable or auto-renewable subscription joins `entitlements`, a sent revocation leaves them, and every purchased or sent transaction stays in `unfinishedTransactions` until finished. `purchaseResults` sets an outcome per product, and `purchaseRequests` records every purchase.
- Lowered the minimum platforms to iOS, Mac Catalyst, macOS, tvOS, visionOS, and watchOS 26.
- Restructured the README for skimming: features, a quick start, common tasks with code taken from the example app, the delivery rules as a table, how to run the example app, and links to the documentation articles. The long-form rules and recipes now live in the articles.
- Added documentation articles: Getting Started, Delivering Transactions, Gating Features, and Handling Errors in `InAppPurchase`, Building a Paywall in `InAppPurchaseUI`, and Testing Purchases in `InAppPurchaseTesting`. `PurchaseStore`, `PurchaseStore.start(handling:)`, and `Entitlement` gain code examples, and every parameter of `PurchaseTransaction.init` is documented.
- Added an example app, `Examples/PurchaseExample`. It sells tips, Pro as a one-time purchase or a subscription, and consumable coins through one `PurchaseStore` and one transaction handler, runs in the simulator against a bundled StoreKit configuration with no signing, and tests its coin delivery with `MockPurchaseClient`.
- Documented purchase integration: the README now covers starting the store, the delivery rules, a tip jar, subscription gating, consumable coins, testing with `MockPurchaseClient`, and previews with `PurchaseStore.preview`, and each module's documentation catalog lists its public types.
- `InAppPurchaseUI` replaces `TipJarView` and `TipJarCopy` with a bridge to SwiftUI. `PurchaseStore.purchase(_:using:options:)` purchases through the view's `@Environment(\.purchase)`, and `refreshingPurchases(_:)` refreshes the store whenever the scene becomes active. For a ready-made storefront, use StoreKit's `StoreView`.
- `PurchaseStore(productIDs:)` now sells through the App Store. Only transactions that pass StoreKit's verification are delivered or counted; a purchase that fails verification throws `unverified`. Every `StoreKitError` and `Product.PurchaseError` maps to a `PurchaseError.Code` with the StoreKit error kept as `underlying`, and an error StoreKit adds later maps to `unknown`. A second store listening for transactions in the same process logs a fault.
- `PurchaseStore` is implemented. `start()` and `start(handling:)` start the transaction listener, compute entitlements, retry unfinished transactions, and load products; the handler receives every transaction at least once, one at a time, and the store finishes it only after the handler returns. With no handler, `start()` finishes non-consumables and auto-renewable subscriptions and leaves consumables and non-renewing subscriptions unfinished until `start(handling:)` supplies one. The handler must not call back into the store: a refresh from inside it returns without waiting for deliveries, and a purchase throws `unsupported`. A subscription counts as owned for as long as the App Store reports it current, which includes a billing grace period. `purchasedProductIDs`, `isEntitled(to:)`, `product(id:)`, `missingProductIDs`, `loadError`, `isLoadingProducts`, `refresh()`, `restore()`, and `preview(products:purchasedProductIDs:)` are added; `entitlements`, `finish(_:)`, `listenForTransactionUpdates(_:)`, and `loadProducts(_:)` are removed, and `products` is an array in the order the identifiers were given. `purchase(_:options:)` returns only after delivery and throws `deliveryFailed` when the handler threw or no handler can deliver a consumable; it is unavailable on visionOS.
- `MockPurchaseClient` is now `Sendable` rather than main-actor isolated, and `init()` takes no arguments. Set `entitlements`, `products`, `productsError`, `purchaseResult`, `syncResult`, and `unfinishedTransactions` instead of `failure` and `outcome`. `finishedTransactions` replaces `finished`, `nextFinishedTransaction()` waits for the next finish, and `send(_:)` delivers a transaction update.
- `PurchaseStore.init(client:)` is replaced by `PurchaseStore.init(productIDs:)`, which sells through the App Store, and, in `InAppPurchaseTesting`, `PurchaseStore.init(client:productIDs:)`, which takes a `MockPurchaseClient`.
- `PurchaseClient` and `StoreKitPurchaseClient` are no longer public. A test or preview uses `MockPurchaseClient`.
- Added `PurchaseError` with an open `Code` and an `underlying` error. `PurchaseError.Code` gains `deliveryFailed`, `invalidPresentationContext`, `networkUnavailable`, `notAvailableInStorefront`, `notEntitled`, `paymentMethodBindingRequired`, `unknown`, `unsupported`, `unverified`, and `userCancelled`. `failedVerification` is now `unverified`, `system` is now `systemError`, and `PurchaseError` no longer carries a `productID`.
- Added `TransactionEvent`, which reports a purchase and a revocation as separate cases.
- Added `Entitlement`, a set of product identifiers that each unlock the same feature.
- `PurchaseOutcome` cases are now `pending`, `success`, and `userCancelled`, and the enum is no longer `Hashable`.
- `PurchaseTransaction` gains `appAccountToken`, `isUpgraded`, and `originalID`, and `purchaseDate` now defaults to the current date. `PurchaseProduct.price` now defaults to zero.
- Removed `VerificationPolicy`. Unverified transactions are never delivered or counted.
